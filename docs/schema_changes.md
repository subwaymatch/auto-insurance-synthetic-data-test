# Schema changes: old table and column names to new

The output tables were renamed and restructured in the release that expanded the vehicle catalog and added
telematics (see CHANGELOG.md). This file maps every table and column of the previous layout to the new one, so
existing case material can be translated. It was generated by comparing the headers of the two layouts.

Conventions in the new layout: table names are singular nouns; columns are lower-case `snake_case`; a key has the
same name in every table that holds it (`policy_id`, never `Policy Number` in one table and `Policy ID` in another).

## Added after the realism audit

## Added with the market and the general ledger

Nothing was renamed or removed, and no column was added to an existing table (see CHANGELOG.md, "After the
audit"). A premium transaction's accounting date is the later of its `effective_date` and `processed_date`;
it is not stored.

| Table | One row per | Columns |
|---|---|---|
| `gl_account` | General ledger account | `account_number`, `account_name`, `account_type`, `normal_balance`, `financial_statement` |
| `gl_journal` | Journal line | `journal_line_id`, `journal_number`, `accounting_period`, `posting_date`, `company_id`, `journal_type`, `source_table`, `account_number`, `debit`, `credit` |
| `agency_statement` | Agency and month | `statement_id`, `agency_id`, `statement_month`, `written_premium`, `commission_amount`, `payment_date`, `payment_method` |

The agency table has 136 rows (was 60): 120 independent agencies, 14 exclusive agents' offices and the two
direct units. Agency names changed with them.

## Records, not totals (the realism audit and its follow-up)

The tables now hold what an insurer's systems record, and leave to the user the totals an analyst works out from
those records (see CHANGELOG.md, "Fixes from a dataset realism audit" and "Records, not totals"). Every removed
column can be rebuilt exactly; `validate.rebuild` in `validate.py` does it in pandas, and the website's data model
page gives the SQL.
